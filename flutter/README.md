# Flow UI

Flutter control-plane app for Flow: menu bar / system tray popover, first-launch onboarding, and the dashboard/settings window. See [`docs/product/vision.md`](../docs/product/vision.md) for the product architecture and [`docs/contracts/`](../docs/contracts/) for the Flutter↔daemon contract, satisfied by both `lib/data/mock_daemon_repository.dart` (the default, for UI-only development) and `lib/data/ipc_daemon_repository.dart` (a real `flow-daemon` process over local IPC — see "Running against a real daemon" below).

## Running it

```sh
flutter pub get
flutter run -d linux   # or -d macos / -d windows, depending on your machine
```

There's no real daemon or OS tray integration yet (see `lib/app.dart`'s doc comment), so the app launches straight into the dev harness — a control strip (View / Connection / Platform / Theme) that drives the same providers every real screen reads, letting you reach every surface and state combination without a daemon:

- **Menu Bar** — the tray popover, anchored to a minimal mock desktop bar.
- **App Window** — the dashboard/settings window.
- **First Launch** — the onboarding flow.
- **All Platforms** — macOS/Windows/Linux tray popovers side by side.

## Running against a real daemon

By default `daemonRepositoryProvider` uses `MockDaemonRepository` — no daemon required, and this doesn't change unless you opt in. To point the UI at a real `flow-daemon` process instead:

```sh
# in one terminal, from the repo root
cargo run -p flow-daemon

# in another terminal
cd flutter
flutter run -d linux --dart-define=FLOW_DAEMON_MODE=ipc
```

This swaps in `IpcDaemonRepository`, which connects to `ws://127.0.0.1:47823` (`flow_core::ipc::IPC_PORT`, `daemon/src/main.rs`) — requires a running `flow-daemon` on that port or every provider stays in `AsyncLoading`/errors out. `flutter test` never needs this flag; `test/data/ipc_daemon_repository_test.dart` exercises `IpcDaemonRepository` against an in-memory fake channel, no daemon required.

## Testing and linting

```sh
flutter analyze
dart format --output=none --set-exit-if-changed lib test
flutter test
```

All three are expected to be clean. `flutter test` is real-time-based, not instant — the pairing flow and toast dismissals run through actual (fake-clock-advanced) delays, so the full suite takes on the order of 10-15 seconds.

## Layout

- `lib/domain/` — pure-Dart contract types and the `DaemonRepository` interface (`docs/contracts/data-model.md`, `daemon-ipc.md`). No Flutter dependency.
- `lib/data/` — two `DaemonRepository` implementations: `MockDaemonRepository` (default) and `IpcDaemonRepository` (real `flow-daemon` over WebSocket; `ipc_codec.dart` holds its JSON<->domain-type conversions, `replay_channel.dart` the late-subscriber-replay primitive both implementations share for their `watch*` streams).
- `lib/state/` — Riverpod providers. `repository_providers.dart` picks the daemon backend (`daemonRepositoryProvider`, see "Running against a real daemon" above); `ui_providers.dart` holds UI-only state (theme, tray-open, toasts) that never mixes with daemon state.
- `lib/core/` — design tokens/theme (`theme/`), platform metadata (`platform_chrome.dart`), and shared presentational widgets (`widgets/`).
- `lib/features/` — the actual screens: `tray/`, `onboarding/`, `app_window/`, and the dev-only `harness/`.
- `lib/app.dart`, `lib/main.dart` — entry point.

## What's not here yet

- Real OS tray/menu-bar docking (a `system_tray`-style plugin). Deliberately deferred until there's a daemon to dock against — see `lib/app.dart`'s doc comment.
- Native platform runners (`macos/`, `windows/`, `linux/`) were generated by `flutter create` and haven't been customized (icons, entitlements, etc.) — they're enough to run the app, not to ship it.

## Environment note

This project's Flutter SDK, in whatever session built it, was vendored locally (not assumed to be pre-installed) — a fresh clone still needs its own working Flutter install (`flutter --version` should report a recent stable release; this project was last verified against 3.47.1) with the `linux-desktop`/`macos-desktop`/`windows-desktop` config enabled as needed (`flutter config --enable-<platform>-desktop`).
